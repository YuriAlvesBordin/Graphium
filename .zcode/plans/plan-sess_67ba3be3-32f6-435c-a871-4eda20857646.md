Edge Bundling Removal Plan

## Overview
Remove all edge bundling-related code and documentation from the Graphium library while preserving core functionality (physics-based layout, rendering, interaction). Edge bundling was implemented as an optional feature in EdgeConflictDetector2D via the `edgeConflictUseBundledRoutes` option and `routeProvider`. This plan removes that feature entirely.

## Files to Modify

### 1. src/physics/EdgeConflict2D.js
- Remove `edgeConflictUseBundledRoutes` from the `DEFAULTS` object.
- Remove `this.routeProvider = null;` from the constructor.
- Remove the `setRouteProvider(provider)` method entirely.
- In `_routePoint(edge, pointIndex, out)`:
  - Remove the conditional block that uses `edgeConflictUseBundledRoutes` and `routeProvider`.
  - Keep only the else block (direct segment calculation).
- In `_buildSegments()`:
  - Replace the pointCount calculation with a constant `2`.
  - Remove the conditional block that uses `edgeConflictUseBundledRoutes` and `routeProvider`.
  - Keep only the else block (direct segment calculation for both points).
- In `_routeSegmentCount(edge)`:
  - Replace the entire function with `return 1;` (since each edge is a single segment without bundling).
- Remove any unused imports or variables that become unnecessary (none identified).

### 2. docs/architecture.md
- Remove the mermaid diagram edge: `GM --> EB[EdgeBundling2D]`
- Remove the bullet point: "- **Physics2D** and **EdgeBundling2D** are the only modules that *write* positions"
- Remove the table row: 
  `| **Custom bundling** | Implement \`RouteProvider\` interface, call \`physics.setRouteProvider\`() (see \`src/physics/Physics2D.js\`) |`

### 3. docs/physics.md
- Remove the option `edgeConflictUseBundledRoutes: false,` from the PhysicsOptions table.
- Remove the optimization tip: "- Edge bundling is not available; use spatial hash for neighbor queries"

## Verification
After these changes:
- The library builds and runs without edge bundling functionality.
- Edge conflict detection (crossing, proximity, overlap resolution) continues to work using direct segments.
- All other features (physics, rendering, interaction) remain unaffected.
- No references to "EdgeBundling2D", "edgeConflictUseBundledRoutes", "routeProvider", or "SegmentGrid" (except where SegmentGrid is still used for conflict detection) remain in the codebase or documentation.

## Notes
- SegmentGrid is retained because it is used by EdgeConflictDetector2D for spatial indexing of edge segments in conflict detection, independent of bundling.
- The `edgeConflictUseBundledRoutes` option is removed entirely; if passed in options, it will be ignored (no longer in DEFAULTS and not used).
- This is a breaking change for users who were using the edge bundling API (setRouteProvider or edgeConflictUseBundledRoutes option).
