## Modo Estrela (edge star) para cliques de 3+ nós

### Objetivo
Nova opção de renderização (desligada por padrão) que, para cada clique (subgrafo completo) com ≥3 nós, desenha as arestas internas como polilinhas de 2 segmentos passando pelo **centro virtual** (centróide das posições correntes): `nó_A → centro → nó_B`. Arestas que não pertencem a nenhuma clique continuam retas como hoje. Feature de renderização apenas — a física não é alterada.

### Abordagem
Reutilizar o hook `routes` já existente (`WebGLRenderer2D.render(model, routes)` / `_fillSegmentData` em `WebGLRenderer2D.js:476`), que renderiza cada aresta como polilinha a partir de um objeto com `getPointCount(index)` e `getRoute(index)`. Um provedor "StarClusterRoutes" implementa esse duck-type.

### Arquivos e mudanças

**1. NOVO: `src/render/StarClusterRoutes.js`** — classe `StarClusterRoutes` (provedor de rotas):
- **Detecção de cliques (≥3 nós)**: constrói adjacência não-direcionada a partir de `model.source/target`; agrupamento guloso de cliques máximos, com nós reivindicados (node-disjoint, sem sobreposição), ordenando por grau descendente; clusters com <3 nós são descartados. Complexidade prática baixa (reconstrução apenas quando a topologia muda).
- **Cache**: reconstrói adjacência+clusters somente quando `model.topologyRevision` muda (incrementado por `addNode/removeLink/setData/clear` — `GraphModel.js:172,439,474,544,600,662`). Mapa `clusterId` por link (`-1` = fora de clique, render reto).
- **Centros por frame**: método `beginFrame()` (stamp) chamado a cada `render()`; centróide de cada clique é computado uma vez por frame a partir de `model.x/y` ao vivo (cache chaveado pelo stamp — evita recomputar a cada aresta; grafos com cliques grandes ficam O(1) por link).
- **Rotas**: `getPointCount(index)` → `3` para links internos de clique, `0` caso contrário (o renderizador trata `<=1` como reta — `WebGLRenderer2D.js:490-491`); `getRoute(index)` → array `[ax, ay, cx, cy, bx, by]` (nó → centróide → nó) reutilizando um único scratch array (o `_fillSegmentData` consome os valores dentro do loop do próprio link antes de chamar de novo).
- Salta self-loops/links com `source === target`.

**2. `src/Graphium.js`**:
- `DEFAULTS`: adicionar `edgeStar: false`.
- Construtor: se `options.edgeStar`, cria `this._starRoutes = new StarClusterRoutes(this.model)`.
- `render()` (`:506`): `this._starRoutes?.beginFrame()` e `this.renderer.render(this.model, this._starRoutes ?? null)`.
- Novo método `setEdgeStar(enabled)` (retorna `this`) — cria/descarta o provedor em runtime.
- `pickLinkAt` (`:426`): quando o modo está ativo, testar a distância contra cada segmento da polilinha (via `StarClusterRoutes.getRoute(index)`), em vez da reta direta — mantém click/hover coerentes com o que é desenhado.
- Exportar `StarClusterRoutes` no bloco de exports.

**3. `src/Graphium.d.ts`**:
- `edgeStar?: boolean` em `GraphiumOptions`.
- `setEdgeStar(enabled: boolean): this` na classe.
- Tipo/classe `StarClusterRoutes` exportado.

**4. `demo.html`**:
- Adicionar uma cena com uma clique K4/K3 (4 nós totalmente conectados + nós isolados) e um checkbox "Modo estrela" chamando `graph.setEdgeStar(...)` para demonstração/verificação visual.

**5. `docs/rendering.md`**:
- Nova seção curta documentando o "edgeStar mode" (gatilho clique ≥3, rota via centróide, limitação: segmentos compartilhados se sobrepõem no centro — comportamento esperado).

### Comportamentos / limitações conhecidas
- Sobreposição de segmentos no centro quando o mesmo nó tem múltiplas arestas no clique (efeito esperado e aceito; controlável por opacidade).
- Física totalmente inalterada; o modo só altera geometria de render.
- Clusters são node-disjoint (cada nó pertence a no máximo um clique-estrela), priorizando cliques maiores.
